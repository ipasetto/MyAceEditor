v344 的参考列表重建和原文件字节一致。v386 有 706 条、v531 有 731 条长记录采用 8 KB 分段，总计 1,437 条；两个压缩文件的 211,911 条记录全部通过解码和 ID 检查。

## 发现并修复的问题

1. v386/v531 的第 26 块 UNIONSCROLL_ESSENCE 为空。实际空列表只有 4 字节数量零，旧逻辑继续读取 payload 长度，把下一列表的数量 28 当作长度，从此错位。已改为仅非空列表读取索引和 payload 长度。
2. 第 155 块 CONSUME_POINTS_CONFIG 的记录为 8,260 字节。其压缩数据由 8,192 字节段及剩余 68 字节段组成，每段先有 little-endian ushort 长度头。旧实现直接当成连续 MPPC 位流，产生截断/尺寸错误。已补上长记录封装解析，并保留连续位流兼容路径；两种路径都要求输入完全消费、输出长度完全一致。
3. 已增加相应 C# 回归用例：压缩空列表、8193/16384/16385 字节长记录、分段与普通流、截断拒绝、可选真实文件目录测试。

## 界面汉化

所有 170 个 CFG 中的 485 个不同数据分类均有中文显示名。保留 NPC、ID、MPPC 等通用缩写；常见字段使用 480 个词汇规则及专用映射，保留编号和原始字段提示。无法确认含义的扩展字段仍保留原始标识，不猜测其语义。游戏文件中的物品名、描述和路径仍读取原始内容。

- C# 字符串和括号词法检查、项目 XML 与 Python 语法检查通过。这些检查不等于 C# 编译。
