# 任务点击卡顿：分析与修复

本轮针对点击“任务”页、选中任务、展开子任务/对话和连续搜索的路径修改源码。没有收到 tasks.data；现有三个真实附件都是 elements.data。环境没有 .NET SDK、C# 编译器、Windows 或 Wine，因而没有复现真实任务界面、执行编译或测量提速。

## 源码中确认的阻塞点和错误

| 路径 | 发现 | 本轮处理 |
|---|---|---|
| QuestFieldHint | 每个任务引用字段都递归遍历全部任务；缺少元素数据时还会提前返回空提示 | TaskIndex 建立一次 ID 字典，直接查询任务；与元素引用分开判断 |
| ShowQuest | 界面线程一次创建全部字段、文本和对话窗口/选项，再调用 ExpandAll | 后台准备字段与提示，32字段一批；隐藏页不建详情；文本/对话延迟绑定，窗口/选项按需展开 |
| RefreshQuests / 展开子任务 | 虽然分批插入，但最终仍在隐藏任务页创建全部根节点；首次显示需创建大量原生树项 | 首次仅创建200个模型节点及续载标记；子任务和对话同样分页 |
| 搜索 | 每个按键都排队筛选、递归遍历与排序，旧工作不会真正取消 | 一次排序的搜索索引，200ms合并，取消旧请求；不再把搜索结果截断为3000条 |
| 切换任务 | 新任务先接管当前对象，旧文本/对话控件随后清空；清空与选择事件可能交错提交 | 切换前提交；编辑区记录所属任务，清空时屏蔽事件，异步结果检查修订号及对象引用 |
| 切换对话 | 旧文本提交后可能改写刚选中新节点的标题 | 单独记录旧编辑节点，只更新与旧对象对应的节点 |
| 字体/绘制 | 每次生成任务分组标题新建字体；主标签绘制的字体/画刷未及时释放 | 任务分组共享字体，绘制资源及时释放；深层缩进保护绘制宽度 |
| 对话预览 | 先处理完整字符串再截取50字符 | 先截取可见前缀，再替换换行 |

以上属于源码分析，可以说明这些路径会增加界面线程工作量或产生状态归属错误；不能据此断言用户现场唯一原因已经复现或消失。

## 操作变化

点击任务后，状态栏显示正在准备/显示的字段。字段按小批填充，快速切换会取消旧详情；任务页未显示时不创建详情网格。打开“文本”或“对话”页才绑定相应控件。对话初始只显示五组入口，手动展开窗口和选项；每次最多创建200项，点击“加载更多”继续。

读取格式仍为原项目实现的 v93 完整结构，其他版本为名称模式。未改 TaskSchema、任务 Build/Save 和元素数据解析/保存规则；启动自动读取仍默认关闭。显示文本未修改时保留原始存储换行和无修改写回路径。

## Windows 验收

1. 解压运行 `build-zh-CN.cmd`，先确认 C# 回归和发布成功，再使用新生成的 `dist\MyAceEditor.exe`。
2. 只打开 tasks.data，确认任务名与任务引用可查看；再加载配套 elements.data，确认物品/怪物提示正常。
3. 在元素数据页加载同目录任务，之后点击任务页；确认列表先出现一段，可继续加载。大列表滚动、子任务展开和深层缩进不应报绘制错误。
4. 连续选择不同任务，确认状态和字段最终属于最后一次选择；切换到文本/对话页，确认只在访问时显示。大量对话不会自动全展开。
5. 反复输入和删除搜索词，点击“加载更多”直至末尾；检查结果没有遗漏、重复或过期搜索覆盖。
6. 在任务A修改文本或对话，再直接点击任务B；确认A的修改仍属于A，B未被误改。切换对话窗口时，旧文本不能覆盖新节点标题。
7. 对副本验证无修改重建字节一致，再修改、保存、检查备份及重读。空任务、名称模式及损坏文件也应有可操作反馈。
8. 多次切换页签和任务，记录实际响应耗时及GDI对象数量变化；当前没有测得的提速倍数或耗时承诺。
