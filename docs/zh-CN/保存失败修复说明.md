# 保存失败：分析与修复

后续复核发现与修补见 [保存功能复核](保存功能复核.md)。本文件保留前轮范围及当时的检查结果。

本轮按元素数据和任务数据两条路径审查源码。未提供具体错误信息，也没有 tasks.data 或 Windows/.NET 环境，因此没有复现现场故障；以下结论来自源码，不表示所有保存失败原因均已排除。

## 源码确认的问题

| 问题 | 本轮处理 |
|---|---|
| 任务备份只精确到秒，且禁止覆盖；同秒保存会重名失败 | 元素/任务统一毫秒时间戳+GUID备份 |
| 任务临时名固定为目标.tmp，写入失败后未统一清理 | 每次使用自身唯一临时名，在finally清理，不覆盖其他残留临时文件 |
| 任务页使用全局“保存”/Ctrl+S仍调用元素保存 | 按当前任务页路由保存和另存为 |
| 元素保存前没有显式结束当前单元格编辑 | 保存前先提交编辑；任务保存也提交文本、网格和当前名称 |
| 新建元素记录按模板清空字段；无模板时字段缺失，byte:N可能为空字符串 | 按CFG读取完整零值记录，再设置ID/名称 |
| 写入与保存后重读混在同一成功/失败分支 | SaveReceipt标记磁盘提交完成；重读失败或取消单独报告 |
| 元素另存为后按新目录加载资源/任务，可能清空旧任务会话 | 保存后重读复用当前资源与任务；正常手动打开文件仍按新目录加载 |
| 字段和文件错误缺少直接定位 | 字段异常附数据块、ID、原始字段名；文件异常附写入/回读/备份/替换阶段及路径 |
| 超长任务名写入会截断 | 仅对已修改名称检查长度并拒绝超长，原始未改名称保持原字节路径 |

## 文件写入流程

后台生成目标字节后，在同一目录创建唯一临时文件；每次最多写入1MiB，Flush(true)后关闭，再逐块回读并与待保存字节比较。覆盖现有文件前创建唯一备份，然后替换；若API明确不支持替换，仅降级到同目录覆盖移动。不对文件占用、权限或空间错误强行降级。

回读比较验证的是临时文件与生成字节一致，不是游戏兼容或压缩重编码验证。保存提交阶段不提供取消，避免磁盘已更新却报取消；窗口保持正常消息循环。保存后重读仍可取消，并明确显示文件已保存、界面重读未完成。写入失败时内存编辑保留；备份已创建而替换失败时备份会保留。

**v386/v531 等 MPPC 压缩元素仍只读。** 未完整读取、有CFG警告、无修改写回校验失败的元素数据也保持只读。文件权限、被游戏/其他软件占用、磁盘空间或文件系统能力仍可导致保存失败；可关闭占用程序或选择可写位置另存为，错误对话中可复制具体诊断。

## Windows 验收

1. 解压运行 `build-zh-CN.cmd`，确认C#回归和发布成功；使用本次生成的EXE。
2. 在任务页只打开tasks.data，编辑后按Ctrl+S；确认实际目标是任务文件。用“另存为”保存到其他目录，再重读核对。
3. 连续保存多次，检查每份备份名称不同，内容分别是对应保存前的数据；预先保留一个目标.tmp，确认它不被覆盖。
4. 编辑元素单元格后直接保存；向空分类新建、克隆含byte:N字段的记录，保存并重读核对ID、名称和定长字节字段。
5. 在副本中输入非法数字、超出字段字节限制的文本或超长任务名，确认错误定位明确，原文件没有被替换。
6. 在Windows用独占句柄占用目标，或选择无写权限路径；确认错误显示阶段、原文件仍在且内存修改保留。随后选择可写目录另存为。
7. 保存完成后取消重新读取，确认提示“磁盘已保存，界面重读未完成”；手动重开核对文件，不把此状态当作写入失败。
8. 元素另存为前，在任务页留有未保存修改；另存元素到新目录后，确认任务及资源会话仍在。测试MPPC只读文件时应看到明确只读原因。
